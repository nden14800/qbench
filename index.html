Rules before rankings

Methodology & principles

QBench starts with a strict separation between observed data, interpretation and any future composite metric.

Current status: task-set draft published. The first original task definitions are published in the Task library. No model has been scored yet, and no leaderboard or composite score is published. This is intentional: the interface must not imply evidence that does not exist.
01 / SOURCE

Evidence provenance

Every result should retain a direct source URL, publication or run date, evaluator identity and relevant run configuration. A source link is not proof by itself; verification is a separate review state.

02 / COHORT

Comparable cohorts

Scores are directly compared only when evaluation name, evaluation version, metric, unit and configuration match. Incompatible measurements remain separate rather than being normalized without justification.

03 / METRIC

Native units first

Keep the publisher's original metric and unit. Higher-is-better or lower-is-better must be explicitly declared in the evaluation definition; the interface never guesses direction.

04 / UNCERTAINTY

Preserve uncertainty

Where available, retain sample size, confidence intervals, run count and variance. A single point estimate should not be presented as more certain than its source supports.

05 / REVIEW

Transparent review state

Records can be marked unreviewed, verified or disputed. Imported data defaults to unreviewed. A status change should be backed by a documented review process.

06 / COMPOSITE

No composite score yet

A single headline score will be considered only after the evaluation set, weighting, aggregation, missing-data policy and sensitivity analysis are specified and independently checked.

Record schema
Expected JSON fields for each observation
Schema 0.1
  • model and provider — exact model/configuration identity and creator
  • evaluation and evaluationVersion — named test suite and its version
  • metric, unit, score — native measurement; score must be numeric
  • direction — higher or lower is better, as defined by the evaluation
  • date, source, configuration — provenance and reproducibility context
  • review — unreviewed, verified or disputed
  • sampleSize, ciLow, ciHigh, latencyMs — optional source-reported details
